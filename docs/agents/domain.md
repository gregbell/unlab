# Domain docs

Before exploring an area of the codebase, read the root
[glossary](../../GLOSSARY.md) and any relevant architecture decision records in
`docs/adr/`. If either is absent, continue with the task.

In prose, write the product name as <https://unlab.run>. Use glossary terms in
issue titles, proposals, and tests. For example, the Manual shows how to capture
traffic on a cable, and an exercise asks the reader to explain why a frame
crossed it. If a concept needs a new term, raise it during domain modeling.

If a proposal conflicts with a recorded decision, cite the decision and explain
why it warrants reconsideration.
